# Rapid Prototyping and Experiments

## Use When

- The team has a promising option but uncertainty remains.
- Stakeholders are arguing abstractly.
- A behavior, workflow, policy, product, or communication change needs testing.
- Building the full solution would be expensive or slow.

## Inputs

- A solution concept or finalist.
- The riskiest assumption to test.
- A user, operator, stakeholder, or system surface where the test can run.
- A time box and acceptable risk level.
- A success, failure, or learning threshold.

## Quick Start

Use a same-day prototype pass:

1. Choose one assumption, not the whole solution.
2. Pick the lowest-fidelity artifact that can test it.
3. Write the expected result before testing.
4. Run the test with real or realistic users/systems.
5. Decide whether to discard, revise, retest, raise fidelity, or implement.

## Procedure

1. Identify the riskiest assumption.
2. Choose the lowest-fidelity prototype that can test it:
   - sketch
   - wireframe
   - storyboard
   - role play
   - checklist
   - process map
   - small live pilot
   - theoretical model
3. Define the expected result before testing.
4. Run the test quickly.
5. Capture observations, not just opinions.
6. Decide whether to:
   - discard
   - revise
   - test again
   - increase fidelity
   - implement

## Template

```text
Solution concept:

Riskiest assumption:

Prototype type:

Audience or test surface:

Expected result:

Actual observation:

What we learned:

Decision:

Next test or build step:
```

## Output

- Assumption tested
- Prototype artifact
- Expected result
- Observed result
- Learning
- Next decision

## Evidence Check

Before leaving this skill, confirm:

- The prototype tested a named assumption.
- The expected result was written before feedback came in.
- Observations are separated from opinions.
- The next decision follows from the evidence, not sunk cost.

## Handoff Prompt

```text
We are using Skill 7, Rapid Prototyping and Experiments. Concept: [concept]. Assumption tested: [assumption]. Prototype: [artifact]. Expected vs actual: [summary]. Decision: [discard/revise/retest/increase fidelity/implement]. Please review whether the evidence supports the decision.
```

## Watchouts

- Do not over-prototype before the learning goal is clear.
- Do not validate only with friendly observers.
- Do not hide failed prototypes; they are learning assets.
