## Recommended Learning Path

When teaching or running the full system from a clean start, use this sequence:

1. Skill 1: frame the measurable problem.
2. Skill 2: observe the real context.
3. Skill 3: map causes and the active constraint.
4. Skill 6: generate a wider option set with brainwriting.
5. Skill 4: narrow with decision hygiene, outside view, premortem, and tripwires.
6. Skill 5: test critical assumptions with appraised evidence.
7. Skill 7: prototype through an MVP or PDSA experiment card.
8. Skill 10: design adoption around stakeholders, barriers, context fit, and fidelity.
9. Skill 8: turn the adopted solution into standard work and sustainment rhythm.
10. Skill 9: run the after-action review and update the system.

## Selection Rule

If a task is fuzzy, start at Skill 1. If a task is already framed and evidence-backed, jump to the earliest missing bottleneck in the recommended learning path.

## Standard Skill Output

Every skill should leave behind a short artifact that another person can inspect without attending the meeting:

- the problem or decision being worked
- the evidence used
- the options considered
- the decision or next test
- the owner and date for the next move
- the adoption or sustainment risk, when behavior change is required

## Facilitator Rule

Do not let a group move forward just because discussion feels productive. Move forward when the required output exists and the evidence check is satisfied.

## Agent Rule

When an AI or operations agent uses these skills, it should state:

- which numbered skill it selected
- why that skill is the next bottleneck
- what artifact it produced
- what remains unproven
